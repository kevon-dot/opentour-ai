# Guided starter proposals without inference

This provider consumes the actual confirmed typed map and supplies only
generated suggestions through the ordinary starter proposal interface. It does
not label cases as owner-adjudicated or grant model/inference/evaluation rights.
The separately authorized case owner still accepts, edits or leaves each case
unresolved before a whole-family freeze.

Before-code acceptance mapping from current OPE-513, OPE-512, OPE-538 and the
shared implementation contract:

| Check | Required behavior | Positive/adverse evidence |
| --- | --- | --- |
| G1 | Actual confirmed-map input | Refuse a draft, unresolved operative branch, missing schema or unavailable current settings; use the adapter's existing current-authority guard |
| G2 | Bounded typed proposals | Presence and finite numeric predicates only; derive threshold/boundary candidates from actual clauses, never infer categorical semantics or future fields |
| G3 | Family identity | Deduplicate the actual decision-time input; stable case/family/template refs cannot multiply independent support by branch annotation or paraphrase |
| G4 | Suggestions are not truth | Include source citation, rationale and generated origin; no owner label, target, split or output observation is produced by the generator |
| G5 | Normal entry and retry | Supply a default pure provider to the existing session; two completed retries reuse its admitted proposal without new generation |
| G6 | Coverage honesty | Report/hold unsupported or excessive candidate spaces; do not claim support for a branch with no reachable reviewed case or silently truncate missing material coverage |

The seven-family categorical P1 oracle remains separate. Presence/numeric
generation cannot be reported as categorical policy interpretation. Optional
authoring inference remains the distinct OPE-552 lane with its own permission
and operation recovery.

The normal entry is `session.propose(guided_case_provider())`. The session owns
current source, map, plan and owner permission. The pure provider consumes no
credentials and dispatches nothing. It constructs generated presence examples
and finite values immediately below, at and above actual numeric thresholds.
It refuses a candidate that cannot be tied to one confirmed branch, unsupported
precision, an unreachable branch or a space larger than 96 candidates. Nothing
is silently truncated or promoted to adjudicated truth.

Variants of the same material branch share one family and template. The purchase
policy therefore yields six generated inputs in three conservative families,
not six independent families. Actual decision inputs determine stable case IDs.
The separate fixed five-family and seven-family acceptance packs retain their
own explicit family provenance. No generated count enters live recurrence.

This slice supplies a normal no-inference provider and its actual case-session
integration. Private UI generation controls, categorical interpretation and the
complete clean-install oracle remain separate integration gates.

For exact reference predicates the guided provider enumerates the authorized rule literals, an absent value and a distinct present value. The existing candidate limit applies to the full product of field choices. It asks the confirmed map for every answer and retains one family per material branch. An uncovered input holds generic proposal generation because a cited answer is unavailable.

The separate P1 deterministic test provider uses invoice category and purchase order as decision-time facts. The owner corrects the freight draft and defers the mixed invoice, whose cited single-category rule has no answer for that input. Owner review and freeze yield seven proposed families, six resolved, one unresolved, two development and four reserved. This is generated case-session evidence. Private Slack authoring and the scored Home readout require their own integration runs.
